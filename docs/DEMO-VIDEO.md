# 演示视频分镜脚本（60–180 秒）

> 目标时长 **约 170 秒**。逐段写清：说什么、点什么、屏幕上应出现什么。
> 每段都标了「可验证的现象」—— 录制时照此核对，不吻合就说明环境没起对。

---

## 录制前：三分钟准备

```bash
# 1. 重置演示库（清空冒烟测试留下的杂乱任务，载入 6 个演示任务）
npm run seed

# 2. 构建并启动（前端构建 + 服务）
npm run start

# 3. 另开一个终端，起公网隧道（→ 这就是要提交的 URL，窗口别关）
./tools/bin/cloudflared.exe tunnel --url http://localhost:8787
```

- 浏览器打开 **http://localhost:8787**（或隧道给的 `https://xxx.trycloudflare.com`）。
- 录屏只录浏览器标签页即可，不必录终端。**建议录 1080p、隐藏书签栏**。
- **录之前先跑一遍不录**：`npm run smoke` 应当 30 项全过；不过就先别录，环境有问题。

## 分镜

### 第 1 段 · 0:00–0:15 — 问题陈述（15 秒）

| | |
|---|---|
| **说什么** | 「个人投资者脑子里是自然语言——『跌破 1200 提醒我』。但现有工具设完之后，你不知道它在干什么：任务在跑吗？今天为什么没提醒？哨兵把这个'解释清楚'当成一等功能。」 |
| **屏幕** | 停在**监控任务**页，顶部露出 6 个演示任务卡片 |

**可验证**：顶栏右侧显示「调度器运行中」且有绿点；页签显示 `监控任务 (6)`。

---

### 第 2 段 · 0:15–0:45 — 说人话 → 可检查的规则（30 秒）

| | |
|---|---|
| **操作** | 在顶部输入框输入：`贵州茅台跌破1200元 或者 涨幅超过5%` → 点【解析】 |
| **说什么** | 「它不去猜。解析成结构化条件后逐条展示给我核对——指标、算子、阈值、数据来源全列出来，我可以改阈值、切 AND/OR。」 |

**可验证**：解析结果里 `最新价 低于 1200 元`、`涨跌幅 不低于 5%` 两条并列，且是 **或** 关系。

**加演（可选，+8 秒）**：改成台面上更难的 `崇达技术近20日累计涨幅大于15%`，
解说「窗口型指标也能解析，且会标注统计口径」。**量比**也可展示（`贵州茅台量比超过1`），
这是今天刚修好的功能。

---

### 第 3 段 · 0:45–1:05 — 诚实边界：解析不了就直说 + 拒绝预测（20 秒）

| | |
|---|---|
| **操作** | ① 输入 `贵州茅台走势健康` → 点【解析】<br>② 再输入 `茅台会涨吗` → 点【解析】 |
| **说什么** | 「① 主观描述我不装作能理解，会明确说解析不了，并给出可替代的说法。② 预测和建议类请求**直接拒绝**，不产出任何规则——这是产品定位，不是能力不足。」 |

**可验证**：① 橙色标出未识别的片段并给替代建议；② 出现合规拒绝提示，
切到**演示与破坏**页的「合规拦截记录」能看到刚才那条被留痕（输入 + 拦截原因 + 时间）。

---

### 第 4 段 · 1:05–1:35 — 触发与证据链（30 秒）

| | |
|---|---|
| **操作** | 回到**监控任务** → 挑一个已触发的任务 → 点【立即评估】→ 展开**证据链** |
| **说什么** | 「每个结论都能沿证据链回到原始字段：来源、数据时点、单位、统计口径、request_id，还能展开原始响应 JSON。**关键数字全部可追溯**——这是题目明确要求的。」 |

**可验证**：展开后能看到 `来源 / 请求参数 / data.timestamp / 统计口径 / request_id / 原始响应`，
以及比较过程（如 `last_price=1312.97 > 1200 → 通过`）。
**注意**：`data.timestamp` 是上游的**数据时点**，不是取数时刻——解说时可以点一句。

---

### 第 5 段 · 1:35–2:10 — 降级：本作品的重点（35 秒）

| | |
|---|---|
| **操作** | 切到**演示与破坏** → 点【数据过期】→ 回**监控任务** → 展开该任务 |
| **说什么** | 「数据过期时，它**不会**说『未触发』。它说『本次**无法判定**——这不等于条件未满足』，并给出数据时点、距今多久、阈值多少。题目要求'不得静默生成正常结论'，这是那条规则在代码里的落地。」 |
| **接着点** | 【源冲突】 |
| **说什么** | 「两个数据源吵架时（0.86% 偏差），**两个值并列展示**，不静默二选一，判为无法判定。」 |

**可验证**：降级文案含「无法判定……这不等于条件未满足」；冲突文案同时出现两个数值。
**别做**：不要只说「降级了」——这段的核心是**文案的具体措辞**，要把那句话念出来。

---

### 第 6 段 · 2:10–2:35 — 恢复 + 风险雷达（25 秒）

| | |
|---|---|
| **操作** | 点【恢复正常】→ 回**监控任务**看恢复通知 → 切**风险雷达** |
| **说什么** | 「数据回来后收到**恢复通知**。雷达按『维度 × 状态』聚合——降级任务在这里是**醒目的盲区**：一眼看出哪些监控现在没有结论。」 |

**可验证**：出现恢复通知文案；雷达页能看到降级维度被高亮。

---

### 第 7 段 · 2:35–2:50 — 收尾：把边界说清楚（15 秒）

| | |
|---|---|
| **操作** | 停在**演示与破坏**页底部的「已知边界与未做事项」 |
| **说什么** | 「最后是这块。数据源目前是**回放**——本项目没有扶摇 API Key，所以用公开行情源抓真实数值、按契约重建信封，界面如实标注为回放，**不假装是实时**。实时接入的 HTTP 传输层还没实现，也写在未做事项里。不做回测、不做涨跌预测——这是产品定位。」 |

**可验证**：`/api/meta` 与界面上都显示「回放 fixture（公开行情源快照重建）」。

---

## 录制时的三个提醒

1. **顺序别乱**：故障注入是**全局**的，第 5 段前请确认是干净状态（顶栏没有黄色「故障注入中」徽章）。
   第 6 段务必点【恢复正常】，否则后面全程降级。
2. **等轮询**：界面 4 秒轮询一次，点完操作**等一拍**再往下说，否则截图时状态还没刷新。
3. **文案是重点**：第 5 段和第 3 段的说服力全在**原话**上。宁可慢一点、把那几句中文念完整。

## 时长不够时砍什么

优先砍 **第 6 段的恢复通知**（口播带过）→ 再砍第 2 段的加演 → 再砍第 3 段的 ①主观描述。
**绝不要砍第 5 段**（降级是全片重点）和第 3 段的 ②（合规红线是硬要求）。
